# Голосовой ассистент записи на консультацию (демо для АУМСОФТ)

Человек открывает страницу, нажимает на микрофон и голосом общается с ассистентом:
задаёт вопросы об услугах (ответы из базы знаний), выбирает время и записывается.
На экране появляется карточка подтверждения с номером записи и файлом для календаря,
менеджер видит запись на странице `/admin` (и, по желанию, получает уведомление в Telegram).

Голос и диалог работают на **Yandex AI Studio Realtime API** (распознавание SpeechKit → LLM → синтез SpeechKit).

## Запуск за 5 минут (macOS / Linux)

1. В [Yandex AI Studio](https://aistudio.yandex.ru) создайте сервисный аккаунт с ролями на модели AI Studio и API-ключ к нему. Запишите ID каталога.
2. В папке проекта выполните:
   ```bash
   ./run.sh          # первый запуск создаст .env и остановится
   # впишите YANDEX_API_KEY и YANDEX_FOLDER_ID в .env
   ./run.sh
   ```
3. Откройте http://localhost:8000. Это демо-страница со встроенным виджетом. Записи менеджера: http://localhost:8000/admin

Лучше говорить в наушниках: так ассистент не слышит сам себя. Перебивать его можно.

## Как показать клиенту

Браузеры дают доступ к микрофону только по **HTTPS** (или на localhost). Есть два варианта.

- **Быстро, с вашего ноутбука:** туннель к `localhost:8000`, например `tuna http 8000` (tuna.am), cloudpub или `ngrok http 8000`. Клиент получит https-ссылку.
- **Стабильно:** в Yandex Cloud через Serverless Containers или ВМ, используя готовый `Dockerfile`. Переменные из `.env` нужно задать в настройках контейнера. Перед публикацией задайте `ADMIN_TOKEN`.

Чтобы встроить виджет на любой сайт, добавьте одну строку:
```html
<script src="https://ВАШ-СЕРВЕР/static/widget.js" data-server="https://ВАШ-СЕРВЕР" defer></script>
```

## Что заменить перед показом

- `kb/*.md` — **база знаний сейчас условная** (типовая метрологическая компания). Её нужно заменить реальными услугами, сроками, адресом и FAQ с сайта клиента. Изменения подхватываются при следующем разговоре, перезапуск не нужен.
- `.env` — `COMPANY_NAME`, часы работы, длительность слота, префикс номера записи.
- `app/agent.py` → `build_instructions()` — характер и сценарий ассистента.
- Голос: `VOICE` (по умолчанию `dasha`), `VOICE_ROLE`. Список голосов есть в документации SpeechKit.

## Архитектура

```
Браузер (widget.js)                    Сервер (FastAPI)                     Yandex AI Studio
 микрофон → PCM16 44.1 кГц ──WS /ws──►  Bridge  ──WSS (Api-Key)──►  Realtime API
 динамик  ◄── PCM16 ────────────────── (ключ не виден браузеру)  ◄── ASR → LLM → TTS
 транскрипт, карточка записи ◄─ JSON ─  выполняет функции:
                                         get_available_slots / book_appointment /
                                         cancel_appointment / request_callback / end_conversation
                                         └─ SQLite (data/), Telegram, SMTP, .ics
```

- Модель **не бронирует сама**: она вызывает функции, а расписание, проверка занятости и защита от двойной записи находятся в нашем коде (`app/booking.py`).
- Перебивание: когда приходит событие `input_audio_buffer.speech_started`, сервер отбрасывает хвост старого ответа, а браузер очищает очередь воспроизведения.
- База знаний: небольшая кладётся целиком в промпт. Большую можно загрузить в Vector Store (`python scripts/upload_kb.py`) и задать `VECTOR_STORE_ID`, тогда включится встроенный `file_search`.
- Транскрипты разговоров сохраняются и видны в `/admin`.

## Следующий шаг: телефон

Логика агента (`app/agent.py`, `app/booking.py`) не зависит от канала. Для звонков нужно заменить только «аудио-трубу»:
- либо SIP-подключение телефонии напрямую к Yandex AI Studio (сейчас в Preview, подключается через поддержку Yandex Cloud);
- либо Asterisk/FreeSWITCH/облачная АТС с передачей медиапотока по WebSocket в такой же `Bridge`, с частотой 8 кГц.

## Проверка без ключа

`tests/mock_realtime.py` имитирует протокол Realtime API и прогоняет сценарий «приветствие → запись → прощание»:
```bash
python tests/mock_realtime.py &
REALTIME_URL=ws://127.0.0.1:8765/v1/realtime ./run.sh
```

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| «Yandex Realtime отклонил подключение (401/403)» | Ключ, `YANDEX_FOLDER_ID`, роли сервисного аккаунта |
| Ассистент молчит после подключения | Поставьте `AGENT_SPEAKS_FIRST=0` и начните разговор первым. Посмотрите ошибки в консоли сервера |
| Ассистент перебивает сам себя | Наушники, или увеличьте `VAD_THRESHOLD` до 0.6–0.7 |
| Обрывает на полуслове | Увеличьте `VAD_SILENCE_MS` до 700–800 |
| Ошибка про голос | Выберите другой `VOICE` (например `alena`) |

## Windows-сервер (обновления через GitHub)

Схема: `git push` → сервер раз в минуту проверяет репозиторий, ставит новый коммит, перезапускается
и проверяет, что работает. Не поднялось — сам возвращает предыдущий коммит. Лог: `data\update.log`.

**Один раз на сервере** (PowerShell от имени администратора):
```
winget install -e --id Git.Git
# закройте и откройте PowerShell заново, затем:
git clone https://github.com/ВЛАДЕЛЕЦ/voicebot.git C:\voicebot
#   для приватного репозитория: https://ТОКЕН@github.com/ВЛАДЕЛЕЦ/voicebot.git
notepad C:\voicebot\.env          # вставьте содержимое своего .env и сохраните
cd C:\voicebot
powershell -ExecutionPolicy Bypass -File deploy\windows\install.ps1
```
`install.ps1` ставит Python и зависимости, выпускает HTTPS-сертификат на имя и IP сервера, открывает порт,
регистрирует автозапуск («Voicebot») и автообновление («Voicebot-Update»).
Прокси: `-Proxy http://адрес:порт`. Корпоративный сертификат: `-PfxPath C:\path\srv.pfx -PfxPassword ...`.

**Дальше:** правите код → `git commit` → `git push`. Через минуту на сервере новая версия.
- Обновить сразу, не дожидаясь: `deploy\windows\git-update.ps1 -Force`
- Состояние и лог бота: `deploy\windows\voicebot.ps1 status|restart|logs`
- Откатиться вручную: `git revert` плохого коммита и `git push`

`.env`, база записей и сертификат в git не попадают и при обновлениях не трогаются.
